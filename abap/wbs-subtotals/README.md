## 前端（通过 BAS 构建、部署）

- 列表绑定 `RunsByWBS`，使用 Fiori elements 的 `AnalyticalTable`。
- 默认 `SelectionPresentationVariant#WBSSubtotals`，分组顺序是公司、年度、期间、分类账、WBS、币种。
- 小计由服务端计算，支持筛选、分页、分组展开；不把浏览器当前加载的行误当成全部结果。
- 禁用叶子层按可见列重新聚合（`aggregationOnLeafLevel: false`），保留明细键，即使用户隐藏某个键列，也不会把不同过账明细混成一条。
- `WbsActions.js` 拒绝小计、合计和分组节点。可用性回调与执行前检查两层保护。
- 明细动作按全部原始键读取 `Runs`，校验原来的操作控制后，再调用原 `Posting` / `OffsetVoucher`；模拟复用 `Simulation.js`。参数弹窗及默认值仍由原动作元数据管理。
- 创建/冲销后刷新分析投影，凭证号意图导航和两列科目描述继续保留。
- 不再使用列表行箭头跳转到旧明细路由；凭证号链接仍可跳转管理日记账分录。

## 金额口径

保留原金额来源：年累计余额。完整 WBS 小计的键是公司＋年度＋期间＋分类账＋WBS＋币种。
同一 WBS 在不同时期分别小计，不将它们合成一个“期间发生额”。分析表的上层合计/总计只代表当前结果中金额值的求和；查询包含多个期间时，该数字不能解释为区间发生额。
如果业务需要“期间发生额”或“多期末只取最新余额”，必须另行调整取数规则，本版本不做这一变化。

## BAS 验收

1. `git pull --ff-only origin main`，保留团队自己的 `ui5-deploy.yaml` 修改。
2. `npm ci`、`npm test`、`npm run build`。
3. 预览/部署按团队流程进行。首次使用标准视图，必要时重置旧表格变式，以加载默认分组。
4. 选择一个公司、一个年度和一个期间，按 WBS 展开，逐组核对明细金额与小计。
5. 多公司、多币种、多期间时，确认各组不混淆；分页滚动后小计不变化。
6. 小计/合计行不能执行凭证操作；明细行的模拟、创建、冲销参数和过账状态正常。
7. 点击已过账凭证号验证标准应用导航。

仅在验收环境按授权测试财务动作，本地单元测试和本次接口验证未执行实际过账或冲销。
